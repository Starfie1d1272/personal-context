# 开放问题

> 更新：2026-10-17。以下探索方式均为可选路径，按实际时间与需要推进。当前选择见[设计状态](design-state.md)。

## 数据语义与最小结构

怎样让共同骨架容纳测量、物品、论文、偏好、目标和 Skill，同时控制字段与维护成本？状态应保存为记录还是由事件计算？多个应用中的同一对象如何对应？

**当前倾向：** 保留语义区别，用少量公共字段连接领域结构和原始材料。类型数量、表结构及是否使用图数据库保持开放。

**可选探索：** 用架构中的三个合成案例逐项映射现有接口，记录无法表达、容易混淆或需要重复维护的部分。只有实际查询需要时才引入更多结构。

## 更新、冲突与时效

哪些来源可以自动更新哪些字段？如何区分补录、现实变化和纠正？人工纠正如何传播到后台抽取、摘要、索引与 Skill？删除后如何处理派生内容？

**当前倾向：** 分开事件时间与记录时间；推断保留来源；修订与依赖显式关联。授权、偏好与外部事实各自判断，按操作影响安排人工确认。

**可选探索：** 走一遍“转赠后补录旧订单”“更正后再次导入原件”“来源撤回”流程，观察旧状态会不会重新出现，并记录具体触发路径。

## 召回与适用范围

内容相关但不适用于当前对象时，哪一环节识别？如何在有限预算下保留重要反证？本地查询、全文检索、嵌入和模型各承担什么？当前证据不足时如何表达？

**当前倾向：** 先落实访问范围与已知对象，再生成候选；权限检查覆盖每次外发。保留时间与适用条件，允许不注入。

**可选探索：** 选择少量日常问题，查看候选与最终输出，分别记录遗漏、错误对象、过时信息和授权问题。比较不同模型或检索方式可以在需要时进行。

## 人的使用与维护成本

日常界面应优先显示什么？哪些建议应合并呈现，哪些可以自动完成？系统如何解释一次错误使用，让人找到可操作的纠正入口？

**当前倾向：** 以当前信息和常用操作为主，来源与冲突按需展开。已有专业应用和 Viewer 可先使用，新增界面由具体需求决定。

**可选探索：** 画出一个物品录入到纠正的流程，记录用户需要理解的概念和执行的动作；试用时观察哪些确认被忽略、哪些信息难以找到。

## 集成、迁移与运行环境

MemOS 的正式接口能覆盖哪些个人对象？如何协调多个插件注入？DSH 的配置机制是否足以准备上下文与能力？导出、换引擎和跨设备怎样保留修订及使用约束？

**当前倾向：** 先选兼容版本并检查接口，以配置和小型扩展推进。独立数据库、统一提供方契约、运行时编译器和发行包均按需要决定。跨设备同步尚未设计。

**可选探索：** 建一张字段与操作映射表，体验一个隔离流程；再尝试导出和读回，检查来源、历史与限制是否完整。无 API 的来源可以先手工导入。

## 经验与能力的演化

怎样从一次任务形成有条件的 Skill？新环境和失败记录如何限制旧方法？已有经验是否能减少重复探索，或帮助更低成本模型完成任务？

**当前倾向：** 经验记录、方法候选与经过验证的方法保留各自状态；同一来源的重复使用不增加独立证据。

**可选探索：** 在一次真实重复任务中记录使用了什么方法、适用条件和结果。对比实验和长期测量可以随后开展；对外只报告实际做过的检查及其范围。

这些问题可以通过设计讨论、配置尝试和小型实现逐步回答。完整产品、模型训练和大规模评测均不作为公开设计的前提。
