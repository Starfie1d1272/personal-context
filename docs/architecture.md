## 1. 系统边界

Personal Context 不重新实现：

- Agent 运行时；
- LLM 提供方系统；
- 完整记忆操作系统；
- 完整 RAG 技术栈；
- Skills 运行时；
- Git；
- Zotero；
- 财务软件；
- 家庭资产软件；
- 通用本体。

核心负责的是：

```text
个人数据模型
+ 来源追溯与权威性
+ 生命周期
+ 更新修改建议
+ 上下文组装
+ 披露策略
+ 用户治理界面
```

## 3. 结构化控制面

### 3.1 逻辑实体

当前建议的最小逻辑对象：

```text
实体
状态
主张
Skill
证据引用
修改建议
关系
策略
范围
修订
上下文编译记录
```

这不是最终数据库 Schema。

### 3.2 状态

状态表达：

> **当前认为“现在是什么”。**

可能需要的元数据：

```text
subject / entity
key
value
valid_from
valid_until
observed_at
verified_at
来源 / 证据引用
权威性
confidence
时效性
sensitivity
status
supersedes / superseded_by
```

状态重点是当前性与权威性。

### 3.3 主张

主张表达：

> **某个主体提出或支持的可论证判断。**

需要允许：

```text
支持
反对
限定
范围
置信度
来源归属
```

主张不采用状态的“新值覆盖旧值”语义。

### 3.4 Skill

Skill 可以拆成：

```text
结构化元数据
├── 前置条件
├── 适用性
├── 可靠性
├── 验证标准
├── 历史
└── 生命周期

内容 / 可执行部分
├── Markdown 指令
└── 代码 / 工具 / 工作流
```

### 3.5 证据引用

Personal Context 不必复制所有原始数据。

证据引用应能够指向：

- DSH 会话 + seq；
- 工具调用/结果；
- Git 提交；
- 文件 + 范围；
- URL；
- 论文 / 页码 / 图表；
- API 记录；
- 外部提供方对象。

## 4. 写入路径：信息沉淀

### 4.1 默认流水线

```text
新事件
  ↓
证据捕获
  ↓
候选提取
  ↓
资产分类
  ↓
权威性评估
  ↓
冲突检测
  ↓
修改建议
  ↓
治理
  ↓
写入 / 拒绝 / 修订
```

### 4.2 为什么不允许模型直接写入

例如：

```text
用户：最近 Codex 好像老断。
```

首先应该得到：

```text
证据：
用户报告反复断连
```

而不是直接得到：

```text
状态：
Codex 连接 = 中断
```

更不能直接得到：

```text
主张：
日本节点不可靠
```

这三者需要不同的证据门槛。

### 4.3 权威性

不同来源应有不同权威性。

例如：

```text
git remote -v
```

对于 repository.remote 的权威性通常高于一次模型总结。

具体权威性模型仍未冻结。

### 4.4 治理分级

候选模型：

```text
自动写入
静默修改建议
批量审查
即时审批
绝不推断
```

当前只确认“必须分级”，不确认最终五级设计。

## 5. 读取路径：上下文组装

### 5.1 活动

顶层触发不是只有任务。

可能包括：

- 任务；
- 查询；
- 记录；
- 对话；
- 事件；
- 计划；
- 系统探针。

活动决定是否：

- 只记录证据；
- 查询状态；
- 召回记忆；
- 加载 Skill；
- 运行 Agent；
- 生成修改建议。

### 5.2 硬性范围

优先使用确定信息缩小范围：

```text
当前用户
工作区
项目
会话
Agent
预设
模型
工具
显式实体
领域
隐私范围
```

### 5.3 候选检索

可以并行使用成熟组件：

```text
精确结构化查询
FTS / BM25
向量检索
图查询
时间查询
记忆提供方
文档提供方
Skill 提供方
```

Personal Context 不应发明自己的全套检索技术栈。

### 5.4 融合 / 重排序

候选可以使用：

- RRF；
- 加权融合；
- 专用重排序模型；
- 小型分类器。

这些是基础设施，不是项目创新重点。

### 5.5 类型感知处理

不同资产进入最终上下文前使用不同规则。

#### 状态

考虑：

- 当前；
- 权威性；
- 有效性；
- 时效性。

某些当前状态可能是强制上下文，而不是普通相似性候选。

#### 主张

考虑：

- 范围；
- 置信度；
- 支持性证据；
- 矛盾。

如果存在关键冲突主张，不能只选择最高分一条造成选择性证据。

#### Skill

考虑：

- 前置条件匹配；
- 环境兼容性；
- 可靠性；
- 历史成功 / 失败。

### 5.6 上下文预算

上下文必须有显式预算。

可以分层：

```text
L0 指针
L1 摘要
L2 完整内容
```

需要时再展开。

### 5.7 披露

最终披露必须晚于相关性判断，并使用确定性规则：

```text
候选
  ↓
身份 / 范围
  ↓
敏感度
  ↓
目标模型 / 提供方
  ↓
策略
  ↓
脱敏 / 拒绝 / 允许
  ↓
序列化
```

敏感数据泄露不能依赖重排序模型“大概率不选中”。

## 6. 上下文编译记录审计

每次上下文组装应产生可审计记录，例如：

```text
Agent 上下文编译记录

活动：
  安装项目依赖

Agent：
  DSH / 代码预设

已包含：
  当前项目
  当前操作系统
  package_manager = pnpm
  dependency-install Skill

已排除：
  health/*
    原因：披露策略

  unrelated-project/*
    原因：不相关

来源：
  Personal Context 状态
  DSH 会话
  Skill 提供方

token：
  ...
```

这是用户界面和调试的重要基础。

## 7. DSH 集成

第一实现预计利用：

### 会话日志 / 会话查询

作为主要证据来源之一。

Personal Context 保存：

```text
证据引用:
  session_id
  seq
```

不复制一套聊天历史数据库。

### 存储 / 存储域

可以作为第一实现的结构化持久化底层。

但核心领域语义不能和 DSH 实现强绑定。

### `agent/pre-step`

适合作为上下文组装的重要集成点：

```text
活动
→ Personal Context
→ 编译
→ 最终上下文
→ 模型
```

### Profile / Bundle / Preset

可以组合：

- Personal Context；
- 记忆提供方；
- Skills；
- GA 启发的演化；
- 领域包；
- UI。

这是一种交付/组合方式，不是核心创新。

## 8. 记忆与学习提供方

当前原则：

```text
记忆提供方
→ 候选记忆 / 经验 / 已学习策略

Personal Context
→ 当前权威语义 / 治理 / 组装
```

MemOS、OpenViking、Graphiti 等都可以成为提供方或基线。

提供方的派生输出不能默认覆盖当前权威状态。

---

## 9. GA 启发的学习闭环

保留 GA 的两个重要思想：

- 上下文信息密度；
- 经验 → 可复用 SOP / Skill。

但降低以下设计的权力：

- LLM 自己维护文本事实库；
- 小型 Markdown 索引作为权威状态发现；
- 模型自己决定所有事实何时应该读取；
- 经验自动变成世界事实。

可能的独立组件：

```text
experience-evolver
skill-evolver
```

## 10. 运行时编译器假设

上下文编译器解决：

> 模型应该看到什么？

运行时编译器可能解决：

> Agent 应该拥有什么？

例如：

```text
当前环境
→ 选择工具
→ 选择 Skills
→ 预设修改
→ 运行时默认配置
```

它的目标是让执行框架（Harness）承担部分原本依赖模型能力的工作。

需要用基准测试证明独立价值。

## 11. 用户界面

当前候选信息架构：

```text
概览
实体
知识
Skills
活动
来源
```

### 概览

- 当前关键状态；
- 过时 / 需要复查；
- 待处理修改建议；
- 最近变更。

### 实体

- 人；
- 项目；
- 设备；
- 资产；
- 应用；
- 研究主题；
- 其它领域实体。

### 知识

- 主张；
- 支持 / 矛盾；
- 范围；
- 不确定性。

### Skills

- 前置条件；
- 可靠性；
- 使用历史；
- 失败历史；
- 修订。

### 活动

- 输入；
- 工具结果；
- 证据；
- 修改建议；
- 写入；
- 上下文编译记录。

### 来源

- DSH；
- Git；
- 文件；
- Zotero；
- 记忆提供方；
- APIs；
- 系统探针。

## 12. 外部来源

不要假设所有权威数据源都能直接连接。

第一阶段优先：

```text
DSH 会话
工具
工作区
文件
Git
系统探针
显式用户输入
```

开放 API / MCP / 本地优先应用是后续高价值适配器。

闭源、跨设备、无 API 应用的接入策略仍是待解决问题。
