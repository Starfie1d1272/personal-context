# 愿景

> 更新：2026-10-17。本文描述期望的使用体验，设计选择见[当前设计状态](design-state.md)。

Personal Context 希望让关于自己及相关世界的信息，在长期生活、学习和工作中逐渐积累，也能随变化得到维护。用户可以直接使用这份积累，并选择交给不同应用与 Agent 的部分。

## 一条信息的完整旅程

买入一件设备后，用户保存票据或简单录入。系统识别对象和购买事件，保留来源；用户打开物品页面就能查看当前拥有情况、位置和维护记录。

在配置工作环境时，Agent 获得这台设备的当前信息及适用工具和经验。之后设备转赠，系统根据明确记录更新拥有状态，历史购买记录仍可查询。若一次回答仍引用它作为现役设备，用户可以查看来源并纠正；后续处理继续尊重这次修正。

录入、查看、按需使用、现实变化和反馈更新共同构成日常体验。输入可以来自语音、文件、工具结果或已有应用，清楚的变化按规则处理，疑点集中呈现给用户。

## 多领域各自保留含义

| 活动 | 用户希望维护的内容 | 使用时需要保留的区别 |
| --- | --- | --- |
| 生活与物品 | 衣物、家电、购买与处置记录 | 买过、仍拥有、正在用与个人评价 |
| 设备与工作 | 当前配置、项目进展、排查经验 | 历史环境、当前状态与方法适用条件 |
| 学习与文献 | 论文、原始数据、观点和自己的笔记 | 作者报告、作者解释与自己的判断 |
| 计划与日常记录 | 待办、意向、完成情况与语音闪记 | 打算做、尝试过与实际完成 |
| 个人资料与账目 | 自己选择保存的记录及来源 | 访问范围、有效时间与专业应用原件 |

同一份系统可以连接这些信息。具体领域由合适的应用和扩展承担，逐步增加支持范围。

## 使用信息时有连续性

隔一段时间继续一个项目，用户能够看到此前进展、当前状态和未确认之处。换用另一个 Agent 时，可以带上所需资料及来源、修订和使用约束。项目内容与个人私密记录按活动隔离，数据流向可检查。

没有找到记录时，系统应说明覆盖范围与未知部分。知识讨论保留有价值的分歧；一条方法经过多次使用后，其适用条件和失败记录也随之完善。未来可以探索已有经验能否减少重复查找、工具调用或模型成本，实际效果由使用记录说明。

## 人的界面与控制权

日常界面优先显示当前信息和常用操作。用户能查到一条认识来自哪里、为什么变化，以及本次活动为什么使用了它。需要时再展开证据、历史、权限和待处理冲突。

低影响更新可以自动发生；需要人工判断的部分应具体、可理解。用户纠正后能看到结果，并能撤回或导出自己的资料。维护负担应与获得的便利相称。

## 从整合开始

DSH 是首个工作环境方向，MemOS、工具、Skills 与专业应用可以组成一个适合个人使用的组合。先完整走通一个物品或设备流程，再根据需要扩展到论文、项目和其他领域。

系统的长期目标是让用户与 Agent 共享一份有依据、可修订、按活动使用的认识。各阶段的具体配置和实现随实际探索逐步形成。
