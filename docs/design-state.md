# 当前设计状态

> 更新：2026-10-17。本文集中记录长期原则与当前选择；具体机制见[架构](architecture.md)，历史见[八月笔记](design-notes/2026-08-16-convergence.md)。

## 系统定义

Personal Context 是一套由用户拥有和掌控、围绕自身及相关世界组织信息的系统。它将个人记录、现实状态、知识、观点与经验维护为有来源、可更新、可纠正的长期资产，供人直接使用，也按当前活动为不同 Agent 准备上下文、工具和技能。

“个人”表示所有权、相关性和使用范围；“上下文”是面向某次活动的输出；“长期认知”描述持续维护的内容。世界模型在这里表示外部、局部且可修订的认识，不预设模型训练路线。

阶段采用“系统设计与渐进探索”。实现可以从已有运行时、记忆组件和插件逐步组合，系统目标继续覆盖生活、学习、工作与知识管理。

## 长期原则

1. **用户掌控与本地优先。** 核心信息和选择机制优先在本地，用户可查看、编辑、导出、迁移和删除，并决定外部服务能处理什么。实际数据流向需要可见。
2. **控制面结构化，内容面自由。** 对象身份、来源、时间、范围、关系和修订规则应可查询、可约束；PDF、图片、数据表与 Skill 正文保留合适的内容形式。
3. **保留语义与证据。** 观察、状态、主张和方法按各自含义处理。用户决定自己的意图和授权；外部事实仍需保留证据与不确定性。
4. **认识随现实变化。** 保存历史，区分新变化、补录与纠正，记录过时、撤回和重新确认。人工纠正应持续生效。
5. **按活动提供。** 核对对象、时间、条件与权限，再选择必要信息和能力。证据不足时允许返回未知或空结果，相关的反证应保留。
6. **自动维护有边界。** 来源明确、规则清楚的变化可自动处理；模型推断保留归属与依据，冲突进入适当处理流程。按影响分配人工注意力。
7. **使用过程可追查。** 一次上下文组装有明确责任方，能说明实际提供了什么、来自哪里、依据哪些规则。多个插件的注入路径需要协调。
8. **人可以直接使用。** 日常界面以当前信息和常用操作为主，来源、历史和冲突按需展开。
9. **事件驱动、增量接入。** 由录入、工具结果、现实变化或明确计划触发处理。专业应用继续负责原始业务数据，接入按可用接口逐步推进。
10. **复用与可迁移。** 优先采用正式接口，导出时保留语义和修订关系。组件选择与自研范围根据实际流程调整。

## 当前选择

| 选择 | 当前倾向 | 保持开放的部分 |
| --- | --- | --- |
| 运行环境 | DSH 为首个集成方向 | 具体兼容版本、跨运行时适配 |
| 记忆与经验 | 优先考察 MemOS 和已有插件 | 领域映射、修正接口、策略协调 |
| 数据表达 | 共同元数据＋领域字段＋原始材料引用 | schema、存储引擎、是否需要附加数据库 |
| 语义区分 | 保留观察、状态、主张、Skill 的不同更新方式 | 类型数量、物理表和接口划分 |
| 上下文与能力 | 根据活动准备数据、工具、Skills 与权限 | 是否需要独立“编译器”组件 |
| 首个流程 | 物品或设备的记录、使用、变化与纠正 | 具体示例、配置与小型扩展 |
| 交付方式 | 集成说明、配置、合成示例及必要适配 | 是否发展为整合包、是否拆分仓库 |

这些是设计选择，具体上游能力和限制以[相关工作中的固定版本证据](related-work.md)为准。

## 2026-10-17 的修订

本轮恢复个人信息管理、人用界面和 DSH 组合探索在整体中的位置，并集中整理如下判断：

- 状态、主张、Skill 是有用的语义区别；实体、事件、原始数据等也可以有自己的结构，分类不要求穷尽且互斥。
- MemOS 已具备结构化存储。先检查它的正式接口和领域映射，再决定补充什么。
- 不预设必须自建独立主库、治理服务或运行时编译器；逻辑职责可以由现有组件承担。
- 真实变化、工具事件和用户编辑都能触发更新，写入按来源和影响分级。
- 权限与披露检查从候选获取开始，在每次外发前生效，并在最终输出时复核。
- 对比实验可作为后续选项；本阶段通过清楚的设计、完整案例和适度集成继续推进。

原始动机保留在[起源](origin.md)中。八月笔记保存当时的判断，当前实施以本文和架构文档为准。
